# Lab records

The house style for university lab records, taken from the 23AID304 High-Performance and Cloud Computing labs. One record can hold one experiment or several.

## Front matter

Copy the logo next to `doc.md` first: `cp ~/.claude/skills/folio/assets/amrita-logo.png .`

The cover stacks the logo, the bold title, the course in italics, then SUBMITTED BY with name and roll number, UNDER THE GUIDANCE OF with the guide, then the date. Sections number `i.`, `ii.` within each experiment, code sits in light framed boxes, and tables are ruled with a shaded header. Skip the TL;DR for lab records unless the user asks for one.

Name the PDF `Ritesh_Roshan_<roll>_Lab<n>_<Title_With_Underscores>.pdf` with `-o`.

## Each experiment

Every experiment is one `#` chapter, such as `# Experiment 4: Identify First and Last Process using Rank`, with exactly these sections in order:

1. **Problem statement.** The task as set, word for word.
2. **Theory.** `### Concepts` as bullets, each led by a **bold term** or an `API_call` and one plain sentence. Then one `###` on the method: the condition used, the execution steps, or the data split, with a table when there is data.
3. **Program.** The complete source, verbatim from the `.c` or `.cu` file.
4. **Compilation and execution.** The exact commands: `mpicc -Wall -Wextra x.c -o x` then `mpirun -np 4 ./x`, or `nvcc x.cu -o x` then `./x`.
5. **Output.** Real output pasted from a run, one `text` block per run, each starting with its `$` command. Include an edge case (one process, a count that does not divide) when the program handles one.
6. **Result.** One paragraph: what the run showed, with the **numbers** in bold, and why any odd ordering occurs.

## The code

Write the program before the record, run it, and save the terminal output to `run.txt`. The record quotes that file and never invents output.

- **One file per experiment**, named for the task: `mpi_vector_sum.c`, `exp7_vector_add.cu`.
- **Constants as `#define N 8`** at the top, with test data generated by formula (`A[i] = i + 1`, `B[i] = 10 * (i + 1)`) so results can be checked by hand.
- **Short names that match the problem**: `rank`, `size`, `chunk`, `local_sum`, `total`, `A`, `B`, `C`. Device buffers take a `d_` prefix. Small `static` helpers such as `print_array` handle repeated output.
- **Guard the inputs.** Check divisibility or bounds, let rank 0 print the error to `stderr`, call `MPI_Finalize` and return 1. Kernels guard with `if (i < n)`.
- **Only the master owns full arrays.** Rank 0 prints the final result after the collective; per-rank lines show what each process did.
- **Comments say why** in one lowercase line: `/* every rank gets the same count, so size must divide N */`.
- **Lines within 64 characters**, K&R braces and four-space indents, so listings never wrap in the PDF.
